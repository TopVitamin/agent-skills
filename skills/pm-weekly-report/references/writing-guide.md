# 周报写作指南

本指南用于整理碎片、直接成稿和润色。先按当前模式判断需要采用哪些规则：整理碎片按主文件完成两轮确认；直接成稿尊重用户“不提问”等要求并按材料保守表达；仅润色保留原有结构和事实。指南中的结构、数量和句式是适用时的写作约定，不授权补造事实。

## 周报结构

完整周报按“本周完成工作 → 本周工作总结 → 下周工作计划”组织。用户只要求其中一个模块时，不擅自扩展；标题或周期可按用户习惯添加。周期已明确时使用用户提供的范围，未明确且不影响正文时省略日期，不按当前日期猜写历史材料。

### 本周完成工作

采用“模块 → 项目或工作类别 → 具体事项”三层结构。

- 默认分为3—6组，每组2—5条。按真实工作内容归并，不要求各组条数相同。
- 材料不足时依主文件先查漏并确认；确认无更多材料后按实际数量呈现。超出数量范围时优先合理归并，不能归并则说明并确认方案，不编造、重复、机械拆分或静默删项。
- 模块及项目标题不加冒号、句号等末尾标点，层级依次递进。事项用无序列表，每条以中文句号结尾；续行对齐正文，不用空格造层级，不默认嵌套子列表。
- 一条围绕一项具体工作。紧密相关的动作和结果可以合并，性质不同的事项分开。通常用一至三句话交代，不为字数或条数拆分。
- 可以写本周仍在推进的事项，准确表达阶段；“本周完成工作”这个模块名不表示每件事都已完成。
- 排序结合用户关注点和实际重要性提出建议，并在第二轮确认。

### 本周工作总结

提炼当周最值得读者快速了解的信息，以及用户在工作中形成的认识。按实际内容选择重点，不固定角度、句数、字数或顺序。

- 用简短自然段表达，不逐项重述完成工作，不默认添加“成果、困难、心得”等小标题。
- 总结可以突出工作重心、关键进展、困难变化、实际效果或心得，但都必须有依据。投入时间多不等于价值最大；阶段进展不等于业务效果；没有新认识时不强求心得。
- 默认整理时，在第二轮说明拟强调的重点并请用户确认；直接写时从材料中选取有依据的重点；润色时保留原有内容范围。
- 可以重复支撑整体判断的关键事实或数据，但省略重复的执行细节。

### 下周工作计划

使用有序列表，条数不限。每条写具体动作和目标方向，按需说明范围、原因、节点或依赖。

- 明确交付可以写具体状态；探索、协调和长期事项可以保留方向性目标，不强求日期、百分比或验收标准。
- 区分个人行动、协调目标和他人承诺。遗留事项仅是计划候选，需确认意向和优先级，不能自动转成承诺。
- 关键事项或节点可选择性加粗，不整条机械加粗。复杂事项按需用缩进子列表；并列说明可用无序列表，有先后关系或需引用时可用与父项对应的编号。简单事项不拆节点。
- 主项和子项均以中文句号结尾。

同一事项可以在完成工作、总结和计划中分别表达实际动作、重要变化或认识、下一步行动。允许必要的关键事实重复，但不重复执行细节；不要求每项跨三个模块出现，也不将所有未完成事项自动转为计划。

## 内容与表达

### 事实与状态

以用户材料和确认作为事实依据。准确区分计划、讨论、方案确认、执行、验证、上线，以及个人贡献和团队进展。可以概括、润色和归并，不能新增事件、收益、原因、责任人或承诺。

信息组织可参考“工作动作＋具体内容＋进展或成果”，按需补充数据、节点和剩余事项。这是内容要素，不是强制句式。写清涉及的功能、场景、规则或问题，以及本周实际推进的内容；既不只报项目状态，也不堆砌个人动作。

动词按实际状态选择：

- “完成”须说明完成对象；完成方案不等于完成开发或上线。
- “推进／跟进”须写明对象和已知进展，不暗示已经完成。
- “参与／协助／组织”须符合真实角色，不把参与改成主导。
- “确认／确定”须确有结论；仍在讨论的方案保持讨论状态。
- “解决／修复／验证通过”须符合实际执行和验证状态，不能用方案已定替代问题已解决。

比例写清对象和分子分母，保持适当精度；累计量与本周新增量不混用。数量和比例不符、统计对象不明或周期歧义影响结论时先澄清。同期指标变化不自动构成因果。任务、修复和项目整体进度分别表达；无可靠数据时用内容、阶段和剩余问题说明，不虚构百分比。

### 常见工作类型

下表提供选词线索，不要求每份周报覆盖所有类型，也不强制替换同义词。

| 工作类型 | 可用动作 | 需要交代的内容 |
|---|---|---|
| 需求调研与分析 | 调研、访谈、收集、梳理、分析、核实 | 场景、问题、已知发现 |
| 出差与现场调研 | 赴现场调研、走访、观摩、核对、交流 | 对象、业务环节、观察或待核实问题；地点仅在有意义时写 |
| 学习与参考 | 学习、参考、研究、对比、整理 | 对象、关注内容、形成的认识或产出；没有应用就不写已应用 |
| 需求与方案设计 | 设计、编写、补充、调整、完善、明确 | 流程、规则、字段或交互的具体内容 |
| 会议与讨论 | 参加、参与、组织、讨论、汇报、协调 | 议题、本人贡献、结论或未决问题；参会不等于形成决策 |
| 评审与决策支持 | 审核、复核、评估、提出建议、协助把关 | 对象、角度、意见、采纳或待决状态；建议不等于最终决定 |
| 研发协作与推进 | 对齐、协调、跟进、推进、协助 | 疑问、范围、进展 |
| 测试与验收 | 走查、测试、核对、验证、验收 | 检查范围、发现、验证结果 |
| 问题排查与处理 | 排查、定位、复现、分析、修复、解决 | 原因、方案、执行和验证状态 |
| 上线与应用跟踪 | 跟进上线、组织试用、收集反馈、观察、复盘 | 范围、反馈、后续处理 |
| 文档与规范建设 | 编写、更新、整理、制定、维护 | 文档内容、评审或发布状态 |

出差、会议和学习是工作方式，通常归入对应项目；确有独立内容时再考虑单独分类，不为凑数新建类别。相同工作使用相同动词可以接受，不能为避免重复而升级责任或成果。

### 总结与计划的写法

总结先判断读者最需要知道什么，以及本周是否形成值得分享的新认识，再决定是否写工作重心、关键进展、困难、实际效果或心得。不要使用空泛结论代替事实，例如“各项工作稳步推进，取得显著成效”；不要把投入时间多当作成果，也不把评审通过写成效率已经提升。不得未经确认替用户写个人感受。

下周计划说明准备做什么、希望朝什么方向推进。目标、步骤、原因、量化和依赖按材料补充，不要求每条都写满。方向性表达可以使用“争取完成”“进一步梳理”“推动进入开发”等；不能把争取事项写成他人的确定承诺，也不能从方案输出直接跳到业务效果。

### 润色与可选句式

主动修正明确错字、口头赘述、混乱语序和重复表达，统一同一对象的称呼。保留有意义的业务细节和用户语气；不要堆砌“赋能、闭环、显著提升”等空泛措辞，也不为显得专业而改变真实含义。含糊处按当前模式澄清、保守概括或省略，不能补造解释。

以下只是可选的组织骨架。括号表示需要由材料支持的信息，缺失时应澄清或省略：

- 完成（交付对象），补充（具体内容），目前（实际状态）。
- 推进（工作），本周完成（具体部分），（剩余事项及其状态）。
- 针对（问题），开展（实际动作），目前（处理进展）。
- 参与（会议或评审），围绕（议题）提出（意见），（已知结论或待决事项）。
- 参考（资料或方案），梳理（关注内容），（形成的认识或后续待验证事项）。
- 协助评估（方案），核对（规则或影响），提出（建议），（采纳或待决状态）。

疑似错字如“数据清晰”须结合上下文判断可能是清洗、梳理还是刷新；含义不唯一时按用户确认处理。总结中的统计口径应自然融入对象描述，不必把内部核查提醒机械写进周报；待验证等重要状态仍须保留。
