# 周报结构

## 适用模式

以下结构用于默认整理及新写正文。仅润色时保留原结构，不按分组、条数或列表规则重构原稿；明确要求直接写时按实际数量组织，省略两轮确认，不因数量不足追问。用户只要求某个模块时，仅应用该模块规则。

## 默认结构

完整周报按“本周完成工作 → 本周工作总结 → 下周工作计划”组织。用户只要求其中一个模块时，不擅自扩展；其他模块须另行确认。

## 本周完成工作

采用“模块 → 项目或工作类别 → 具体事项”三层结构。

- 项目或工作类别控制在3—6个，每组具体事项控制在2—5条。按真实工作内容归并和组织，不要求各组条数相同。
- 材料不足以形成上述数量时，按主文件第一轮流程处理；确认无更多材料时按实际数量呈现。不得编造、重复或机械拆分来凑数。
- 超出数量范围时，优先归并相关内容；不能合理归并时，在第二轮说明并确认处理方案，不静默删掉重要事项。
- 模块、项目或工作类别使用标题，标题末尾不加冒号、句号等标点。全文中模块与项目层级依次递进。
- 具体事项使用无序列表（Markdown 的“- ”），每条以中文句号“。”结尾，不使用编号列表。
- 利用无序列表自身的缩进呈现事项。续行对齐正文，不用手工空格造层级，不默认添加嵌套子列表。
- 一条围绕一项具体工作；紧密相关的动作和结果可以合并，性质不同的事项分开。通常用一至三句话说明，不为字数或条数拆分。
- 可以纳入本周仍在推进的事项，准确表达阶段；标题中的“完成”不意味着所有事项均已完成。
- 排序结合用户关注点和实际重要性提出建议，在第二轮确认。

## 排版示意

以下仅演示结构，括号内容须替换为已确认的真实工作，不是可直接交付的周报。

```markdown
## 一、本周完成工作

### 项目或工作类别一

- （具体事项及其进展）。
- （具体事项及其结果）。

### 项目或工作类别二

- （具体事项及其进展）。
- （具体事项及其结果）。

### 项目或工作类别三

- （具体事项及其进展）。
- （具体事项及其结果）。
```

## 本周工作总结

提炼当周最值得领导或同事快速了解的信息，以及用户在实际工作中形成的认识。依据当周内容选择表达方式，不按固定维度逐一填空。

- 与“本周完成工作”采用同级模块标题，标题末尾不加标点。
- 以简短自然段组织，可按信息量分段，不固定句数、字数、角度或顺序，不套用3—6组、每组2—5条的要求。
- 不按项目逐项重述，不默认设置“成果、困难、心得”等固定小标题；关键事实可以再次出现，但省略重复执行细节。
- 第二轮组织方案中说明这次总结准备强调什么，让用户确认后再成稿。
- 不要求每个项目都进入总结，按本周实际重点选择。

## 下周工作计划

- 与前两个模块采用同级标题，标题末尾不加标点。
- 使用有序列表，不固定条数。每条写具体动作及目标方向，按需说明范围、原因、节点或依赖。
- 关键事项、目标或节点可选择性加粗，不要求每条加粗，不整条机械加粗。
- 复杂事项按需增加缩进子列表。并列说明用无序列表；有先后关系或需要引用时可使用3.1、3.2等编号，保证与父项对应。简单事项不拆节点。
- 主项及子项均以中文句号结尾。不套用完成工作的项目数和条数要求。

## 模块衔接

同一事项可以出现在多个模块：完成工作写实际动作和状态，总结提炼重要变化或认识，计划写接下来的行动及目标。允许必要的关键事实重复，不重复执行细节。不要求所有事项跨三个模块出现，不将全部未完成事项自动转成下周计划。

第一轮统一澄清事实、用户看法和计划意向；第二轮一次确认整份周报的分组、总结重点及计划顺序，再成稿。

## 标题与周期

可按用户习惯增加周报标题及日期范围。周期已明确时使用用户提供的范围，未明确且不影响正文时省略日期；历史材料不自动套用当前日期。
