# 写作规范

本文件适用于各模式。“已确认信息”包括用户明确提供的事实和后续澄清结果。默认整理以两轮确认组织；仅润色保留原稿结构和事实；直接写没有第一轮时，以现有材料保守表达，不补造解释、心得或承诺。

## 本周完成工作

信息组织原则是“工作动作＋具体内容＋进展或成果”，关键数据、时间节点和剩余事项按需加入。这是信息要素，不是强制句式。

写清涉及的功能、场景、规则或问题，以及本周实际推进的内容。既不只报项目状态，也不堆砌个人动作。用自然、具体的中文，保留必要业务细节；不做夸大包装，不为简短删掉关键状态和限制。

材料中已明确的沟通、参与和跟进工作，按实际对象与进展表述；讨论不等于已明确规则或达成共识。

## 动词与状态

动词按实际状态选择：

- “完成”：限定完成对象，完成方案不等于完成开发或上线。
- “推进／跟进”：写明对象和已知进展，不隐含完成。
- “参与／协助／组织”：遵循实际角色，不将参与改成主导。
- “确认／确定”：必须确有结论；讨论中的方案仍写讨论状态。
- “解决／修复／验证通过”：按实际执行和验证状态使用，不以方案已定替代问题已解决。

句式用于组织已有信息，不决定实际工作范围。

## 量化

优先使用有意义、可核实的数量、比例和节点，不要求每条都有数字。比例同时交代对象和实际完成内容。用户只提供定性状态时保留定性表达。

计算比例时明确分子分母、保持适当精度；累计数量与本周新增数量不混用。指标对比的周期或统计对象存在歧义且影响结论时先问。不能仅因两件事同时发生就描述为因果。

## 其他模块

三模块之外的内容仅按用户指定的范围和模板处理。

## 常用动作与表达重点

| 工作类型 | 可用动作 | 需要交代的内容 |
|---|---|---|
| 需求调研与分析 | 调研、访谈、收集、梳理、分析、核实 | 场景、问题、已知发现 |
| 出差与现场调研 | 赴现场调研、走访、观摩、核对、交流 | 调研对象、业务环节、观察或待核实的问题；地点仅在有意义时写，不写出行流水账 |
| 学习与参考 | 学习、参考、研究、对比、整理 | 学习对象、关注内容、实际形成的认识或产出；没有应用就不写已应用 |
| 需求与方案设计 | 设计、编写、补充、调整、完善、明确 | 流程、规则、字段或交互的具体内容 |
| 会议与讨论 | 参加、参与、组织、讨论、汇报、协调 | 议题、本人贡献、实际结论或未决问题；参会不等于形成决策 |
| 评审与决策支持 | 审核、复核、评估、提出建议、协助把关、提供决策依据 | 审核对象、评估角度、意见、采纳或待决状态；提供建议不等于作出最终决定 |
| 研发协作与推进 | 对齐、协调、跟进、推进、协助 | 疑问、范围、进展 |
| 测试与验收 | 走查、测试、核对、验证、验收 | 检查范围、发现、验证结果 |
| 问题排查与处理 | 排查、定位、复现、分析、修复、解决 | 原因、方案、执行和验证状态 |
| 上线与应用跟踪 | 跟进上线、组织试用、收集反馈、观察、复盘 | 范围、反馈、后续处理 |
| 文档与规范建设 | 编写、更新、整理、制定、维护 | 文档内容、评审或发布状态 |

动作库供选择，不强制替换同义词。相同工作使用相同动词可以接受，不能为避免重复升级责任或成果。出差、会议、学习是工作方式，通常归入对应项目；确有独立内容时再建议单独分类，不自动新建类别凑数。

## 常用句式

按信息组织，不机械套用；下列括号仅表示信息位置，缺失内容应澄清或省略，不能补造。

- 完成（交付对象），补充（具体内容），目前（实际状态）。
- 推进（工作），本周完成（具体部分），（剩余事项及其状态）。
- 针对（问题），开展（实际动作），目前（处理进展）。
- 参与（会议或评审），围绕（议题）提出（意见），（已知结论或待决事项）。
- 赴（现场）开展（调研），重点了解（环节），（实际发现或产出）。
- 参考（资料或方案），梳理（关注内容），（形成的认识或后续待验证事项）。
- 协助评估（方案），核对（规则或影响），提出（建议），（采纳或待决状态）。

## 有数据与无数据的表达

有数据时说明对象、统计范围和状态；数量已经清楚时不强求再重复百分比。区分研发反馈已修复、产品已验证和待验证数量。

无数据时用具体产出、内容、阶段、较此前的变化或剩余问题说明进展。复杂排查尚未定位原因，也可以如实呈现已完成的排查内容，不强求包装成结果。只有动作而无内容的记录，依据材料或澄清结果写作，不扩写空泛价值。

## 反面案例与改写边界

下列均为教学示例，不是用户本周事实。右侧仅在假设的原始材料支持时适用，不可照搬其中细节。

| 不要这样写或处理 | 问题 | 应如何处理或表达 |
|---|---|---|
| 参与会议，推进项目落地。 | 缺少议题与真实进展 | 先问议题与贡献；若事实支持，可写“参与采购规则讨论，提出部分收货后的关闭处理建议，待业务确认。” |
| 出差两天，参观仓库，收获很大。 | 行程和感想代替工作内容 | 说明观察环节和已知发现；若材料支持，可写“赴仓库调研收货作业，梳理现场登记方式，差异处理规则待进一步核实。” |
| 学习竞品方案，显著提升产品竞争力。 | 未验证的收益 | 写实际参考内容和产出，不把学习等同于应用或收益。 |
| 主导完成方案决策。 | 原材料可能只是参与讨论或协助把关 | 按角色写“协助评估方案并提出建议”，决策结果已知时再补充。 |
| 完善PRD，优化业务流程。 | 对象过宽，缺少具体变化 | 询问具体章节或规则，确认后写明，不自行增加功能。 |
| 已解决库存异常。 | 原材料只有修复方案已确认 | 写“已确认库存异常修复方案，尚待执行。” |
| 项目整体完成80%。 | 没有统计依据，或只有设计任务进度 | 使用已知阶段和已完成部分，不虚构项目整体百分比。 |
| 本周完成100项。 | 100项实际为累计数量 | 标明累计；本周新增数量不明时不推算。 |
| 上线后指标下降，因此本功能解决了业务问题。 | 把同期变化直接当作因果 | 描述同口径变化及观察周期，不自行归因。 |
| 将一次评审拆成准备、参会、记录三条。 | 为满足最少条数机械拆分 | 合并同一事项；只有独立且有意义的交付才分别描述。 |
| 为达到3个类别，把同一项目重复归入多个类别。 | 重复计算工作 | 先补问是否遗漏，无更多材料则确认按实际数量呈现。 |
| 删除重要事项，以便每组不超过5条。 | 为格式牺牲内容 | 先合理归并，无法归并时提出方案请用户确认。 |
| 项目标题写“采购项目：”，具体事项不加句号。 | 不符合已确认排版 | 标题不加句末标点；具体事项用无序列表并以“。”结束。 |


## 本周工作总结

### 核心原则

根据当周实际工作，动态选择工作重点、关键进展、困难变化或心得认识进行提炼。突出对读者有用的信息，允许有个人判断，但必须有事实依据；不固定角度、句式和顺序，不重复罗列工作事项，不强行拔高。

先判断“领导或同事最需要知道什么”以及“本周是否形成值得分享的新认识”，再选择表达内容。下列维度是思考入口，不是每周必须覆盖的栏目：

- 工作重心及精力投入：时间投入只有在能解释产出、资源占用或困难时才强调；不能依据记录长短推断最耗时的工作，投入多也不等于价值最大。
- 关键进展与实际效果：阶段推进与业务效果分别表达，不强行选出“最大成果”或“最有效果的项目”，也不要求每周都有量化效果。
- 困难与重要变化：说明实际问题、已知影响或需要关注的变化，不为凑结构制造困难，也不掩盖已知关键问题。
- 心得与认识：可以提炼业务理解、方案取舍、协作体会、值得延续或调整的做法，落在具体工作及其依据上，不写空泛感悟。

### 观点依据

总结使用材料及澄清中明确的事实与用户认识；默认整理按第二轮重点组织，直接写选择有依据的重点，润色保留原有内容范围。没有新认识时可以只提炼关键进展或困难，不强求心得。

### 表达思路与可选句式

按当周重点决定从进展、问题、变化或认识开头，不总以“本周主要围绕”起句。下列仅为可选句式骨架，不能机械轮换或补齐缺失事实：

- 工作重心：本周重点推进……，其中……。
- 关键进展：……已从……推进到……，目前……。
- 问题与影响：当前需要关注的是……，已影响……。
- 认识与启示：通过本次……，进一步认识到……；后续类似工作可以……。
- 方案判断：结合……，目前更倾向于……，仍需验证……。
- 实际反馈：从……的统计或反馈来看，……。

“后续可以”仅表示用户确认的启示或建议，不变成已承诺的下周任务。未观察到效果时，不借用效果句式包装阶段进展。

### 去重与风格

用概括后的重点替代执行细节，允许复述足以支撑整体判断的关键结果或数据，不重新列出全部事项。表达具体、克制、自然；有依据的积极成果与尚未解决的问题都可以写。不固定篇幅，不为了凑字数扩写，也不为了简短删掉关键限定。

避免“各项工作稳步推进，取得显著成效”等空泛结论；避免以“投入大量时间”代替成果；避免把需求评审通过写成效率已经提升；避免未经用户确认写出“我深刻认识到”等个人感受。完整表达可按需参照 [脱敏重构案例](examples.md)。


## 下周工作计划

### 表达原则

写清准备做什么、希望朝什么方向推进。已明确的交付可写具体状态；探索、协调或长期事项允许仅有方向性目标。可使用“争取完成”“推动尽快进入”“进一步梳理”，不强求明确日期、百分比或验收标准；但应有真实对象和内容，不能只剩口号。

工作动作与对象应明确；目标、步骤、原因、量化和依赖按材料补充，不要求每条写满。有可靠数量或范围时使用，没有数据时用交付物、阶段或方向描述。量化是表达手段，不是必填项。不能因目标尚不确定而反复追问，只有含义会改变范围、责任或承诺时澄清。

区分个人行动、协调目标和他人承诺：“推动研发尽快进入开发”可以作为努力方向；没有依据时不能改成“研发下周完成开发”。本周遗留事项只是候选，需确认优先级和计划意向，不能自动加入。

| 需求与方案 | 编写、输出、补充、完善、调整、设计 |
| 评审与确认 | 组织评审、提交评审、讨论、核对、确认 |
| 协调与推进 | 跟进、推动、协调、对齐、协助、争取 |

| 学习与探索 | 学习、参考、探索、尝试、验证思路 |
| 规范与沉淀 | 整理、总结、更新、制定、沉淀 |

| 文档与方案 | 需求文档、原型、设计方案、流程图、功能清单、调研记录、操作说明 |

### 目标与进度表达

| 性质 | 可选表达 |
|---|---|
| 明确交付 | 完成……、输出……、提交…… |
| 预期目标 | 计划完成……、争取完成……、以……为目标 |
| 持续推进 | 继续跟进……、进一步完善……、推动……尽快进入…… |
| 探索了解 | 初步了解……、研究……的可行性、探索……方案 |
| 协调促成 | 协调……、推动……确认、争取……支持 |
| 条件性安排 | 待……明确后推进……、结合……情况调整…… |

参考表帮助选词，不强制套用，不因表中存在某个名词就增加原材料没有的范围。可以采用“动作＋对象，重点……，争取……”等组合，也可以简短表达，不固定句式。

避免将“尽快”等词一律删掉或强改为日期；避免把每条计划写成验收清单；避免无内容的“全面推进、有效落地”；避免从方案输出直接跳到已实现业务效果。加粗按重要性选择，不每条开头固定加粗。


## 碎片信息整理与润色

用户提供的是素材，不是必须逐字保留的成稿。主动修正明显错字、口头赘述、混乱语序和重复表达，统一同一对象的称呼，并按动作、对象、当前进展重新组织句子。不要将润色等同于增加事实、升级完成状态或包装成果。

- 明确上下文下，将“刷数据”整理为“刷新相关数据”，将“同频给业务”整理为“向业务方同步上线情况”，将“乱填数据”整理为“自由输入不符合要求的数据”。
- “数据清晰”等疑似错字须结合上下文判断究竟是数据清洗、梳理还是刷新；含义不唯一时采用澄清结果；直接写时保守概括或略去歧义细节，不能一律替换为“数据清洗”。
- “完成了”必须对应用户确认的对象和阶段；删除口语或完成标记不等于认定功能上线。
- “等等”“一些东西”“处理一下”优先用已有具体对象替代；缺少内容时澄清或保守概括，不擅自补上规则、收益或原因。
- 前后矛盾的旧记录和新记录先确认最新状态；不能只挑听起来更好的版本。
- 保留有意义的业务细节与用户语气，不堆砌“赋能、闭环、显著提升”等空泛措辞，不为显得专业改坏真实含义。

低风险措辞调整直接完成；重要事实判断和范围变化按主文件的当前模式处理。

总结直接写进展、影响及剩余工作。统计口径尽量融入对象描述，避免把“不能据此推断”“不代表整体进度”等内部检查规则机械写入周报；确有必要的未完成、待验证等状态仍须保留。
