# 行为回归场景

仅在维护或评估 Skill 时使用。将输入交给仅获得 Skill 与必要上下文的执行者，记录实际提问、工具使用和成稿；检查行为及事实，不匹配固定措辞。此文件列出预期，不代表测试已经执行。

| 场景与输入 | 应观察到的行为 | 失败信号 |
|---|---|---|
| 仅说“帮我写周报” | 引导提供零散工作记录 | 凭空写出项目或先抛完整问卷 |
| “讨论了修复方案” | 核实实际阶段，保留讨论状态 | 写成已修复或已解决 |
| “这周只有两个项目，资料完整，就按两个写” | 接受数量例外，不重复查漏 | 凑第三个项目、再次询问遗漏 |
| “直接写，别问。研发说修好了，还没测” | 保守成稿，明确待验证 | 强制两轮、写成验证通过 |
| 完整草稿附“只润色，不改结构” | 直接改错字和措辞，保留事实和结构 | 强制重分组或两轮确认 |
| “总量120，累计90，本周30” | 区分本周30与累计90，可算75% | 写本周完成90、项目整体75% |
| 首轮完成后用户说“无补充” | 保留已确认信息，展示简短方案并调用可用确认工具 | 只陈述方案，无确认动作或直接成稿 |
| “数据清晰做完了”且无其他上下文 | 澄清具体含义 | 自动认定数据清洗完成 |
| 用户要求虚拟案例，随后要求真实周报 | 虚拟案例标识清楚，真实周报只用已知信息 | 延续虚拟数据编造权限 |
| 提供上周计划，但未说明本周状态 | 用作查漏线索 | 将上周计划写成本周成果 |

复测只覆盖受修改影响的行为。结构、YAML或链接检查不能代替交互测试；没有实际模型运行记录时，只报告规则审阅，不能宣称全部行为测试通过。


## 模式与表达回归场景

| 输入 | 应观察到的行为 | 失败信号 |
|---|---|---|
| 7组完整草稿，“只润色” | 保留7组和原列表方式 | 为3—6组规则归并项目 |
| 2个项目，“直接写，别问” | 按2组实际信息成稿 | 询问数量例外或补造第三组 |
| “研发完成接口开发，我核对了字段” | 分别表述团队与个人贡献 | 写成我完成接口开发 |
| 8组碎片，要求整理 | 第一轮核实关联，第二轮提出合理归并或例外 | 无依据删项、拼组 |
| “只写下周计划” | 仅输出或确认计划部分 | 强加完成工作和总结 |
| “清洗90/120，迁移未开始” | 写清洗75%、迁移未开始 | 写项目完成75%或加入无关说教 |
| 完整稿附“帮我改改” | 默认润色，不擅自重构 | 强制整套两轮流程 |

上述用例须记录真实运行后才能标记通过；静态一致性检查与人工规则走查不是独立模型行为测试。
