# 标注范围

只写当前页面上，原型不能完整说明、但实现或验收需要知道的信息。判断依据是业务后果与信息缺口，而不是固定业务类型。

## 应保留的内容

| 内容 | 说明 |
| --- | --- |
| 状态、模式与准入 | 何时可新增/编辑/审核，哪些字段锁定 |
| 字段约束 | 已确认的必填、范围、精度、默认值、唯一性、校验时机 |
| 计算与联动 | 公式、舍入、重算触发、主数据/快照/回写的业务差异 |
| 操作后果 | 校验、确认、跳转、状态变更、数据更新、失败处理 |
| 权限与数据范围 | 来源明确、影响当前页面行为的角色/权限/数据范围条件 |
| 异常与反馈 | 空态、错误、重复提交、并发冲突及来源明确的提示文案 |
| 查询与列表 | 筛选语义、排序、分页、批量范围等无法从静态页面确认的行为 |

“各项目权限不同”意味着应读取目标项目的权限规则，不能据此删除规则。不要自行补角色矩阵或把按钮隐藏等同于后端授权。

## 通常省略的内容

已在原型中清楚表达且不影响业务结果的布局、尺寸、按钮顺序、圆角、静态标题、Mock 数据、PRD 维护记录通常不用重写。

保留例外：视觉或文案确实承载业务含义时应写明，例如颜色是唯一风险标识、确认正文规定了执行范围。原型与 PRD 冲突时记录冲突，不擅自选择其中一方。

不要强制所有字段、所有组件都有标注。可以把没有额外规则的区域留空；按钮行为简单且已被所属区域覆盖时，不再单独挂角标。

## 内容组织的默认偏好

优先沿用项目已有的清晰约定。没有约定时：

- 同一筛选栏、表格、表单字段组或弹窗聚合为一个标注块。
- 页面级规则使用 `page-global`，不在每个局部块重复。
- 共享状态机等使用 `global`，仅覆盖确实适用的页面；不要把全模块规则装进共享块。
- 操作表优先写“动作 | 条件与结果”，不重复视觉顺序。
- 列表列、只读字段和汇总可以使用四列：`字段 | 展示/输入类型 | 业务说明 | 约束与备注`。复杂公式、来源、编辑条件可以拆列或另表，不能为了固定四列隐藏必要信息。
- 计算规则在来源已定义时写清公式；来源未定义时标待确认，不为了“公式齐全”推算业务。
- 页面定位使用项目可辨认的页面名称、导航或真实路径。面包屑只是一种选择；无面包屑的产品不必新增。

## 来源不足时

区分已确认规则、观察到的原型行为和待确认问题。页面代码只能证明当前实现，不能自动证明业务要求。引用用户已确认的说明时标明来源；补充标注可使用 `A1` 等稳定 ID，但不得把猜测包装成已确认需求。

交付前确认内容没有无依据的数字、权限、状态、金额规则或接口约定；也没有因为裁剪模板而丢失已明确的验收信息。
